# 12｜換設備接手指引

> 給「換一台電腦繼續做這個專案」的人。假設你**完全沒設定過**這台新電腦。
> 每一步都寫了「會看到什麼」與「怎麼確認做對了」。

**不需要搬資料夾。** 所有東西都在 GitHub 上，新電腦重新抓下來就好。
沒進版控的只有可以重新產生的東西（`node_modules`、測試產出、記錄檔），
以及**不該離開這台電腦的登入憑證**。

---

## 0. 離開舊電腦之前（30 秒）

在舊電腦的 VS Code 裡按 <kbd>Ctrl</kbd> + <kbd>`</kbd> 叫出終端機，貼上：

```bash
git status
```

**看到這一行就代表都存好了**：

```
nothing to commit, working tree clean
```

如果看到一堆檔案名稱，代表有東西還沒存。貼這兩行（第二行會把它們送上 GitHub）：

```bash
git add -A && git commit -m "wip: 換設備前存檔"
```

```bash
git push
```

## 1. 新電腦要先裝的三樣東西

照順序裝，每一項裝完都可以先關掉視窗。

### ① Git（把程式碼抓下來用的）

1. 開 <https://git-scm.com/download/win>
2. 下載會自動開始，跑完點開那個 `.exe`
3. **一路按 Next 就好**，不用改任何選項
4. 裝完重開電腦（或至少關掉所有終端機視窗）

### ② Node.js（跑這個專案用的）

1. 開 <https://nodejs.org/>
2. 選 **LTS** 那顆綠色按鈕（版本要 **22 或更新**）
3. 下載後點開，一路 Next

### ③ VS Code（寫程式的編輯器）

1. 開 <https://code.visualstudio.com/>
2. 下載、安裝、一路 Next

### 確認前三樣都好了

打開 VS Code → 上方選單 **終端機（Terminal）→ 新增終端機（New Terminal）**，
下方會出現一個可以打字的區塊。貼上這一行按 Enter：

```bash
node -v
```

**要看到 `v22.` 開頭的版本號**（例如 `v22.11.0`）。再試：

```bash
git --version
```

**要看到 `git version 2.` 開頭**。

> 兩個都顯示「不是內部或外部命令」的話，代表沒裝好或沒重開視窗。
> 把終端機關掉重開一次再試；還是不行就重開電腦。

## 4. 安裝相依套件

按 <kbd>Ctrl</kbd> + <kbd>`</kbd> 叫出終端機，貼上：

```bash

```

會跑一到三分鐘，畫面會滾很多字，最後出現 `added ... packages`。

```bash

```

**要看到 `Tests: 345 passed, 345 total`**（數字可能更多，只要沒有 failed 就對了）。

到這裡你已經可以改程式、跑單元測試了。下面幾項是「要做那件事才需要」。

## 5. 要跑完整測試才需要的（可以之後再裝）

### Java（Firestore 模擬器要用）

`npm run test:rules` 與 `npm run test:fn` 需要它。

1. 開 <https://adoptium.net/>
2. 下載 **Temurin 17** 或更新版的 Windows 安裝檔
3. 一路 Next
4. 關掉終端機重開，打 `java -version`，看到 `17.` 或更新就對了

### Playwright 瀏覽器（E2E 測試要用）

```bash
npx playwright install chromium
```

會下載約 150MB，跑一次就好。

想確認什麼都沒漏，把這四行一行一行跑過：

## 9. 常見狀況

| 你看到 | 意思 | 怎麼辦 |
|---|---|---|
| `'git' 不是內部或外部命令` | Git 沒裝好或沒重開視窗 | 關掉終端機重開；還不行就重開電腦 |
| `npm ci` 卡住很久 | 正常，第一次要下載很多東西 | 等它跑完，通常 1–3 分鐘 |
| `Tests: ... failed` 而且提到 `browserType.launch` | Playwright 瀏覽器沒裝 | 跑 `npx playwright install chromium` |
| 測試提到 `emulator` 或 `java` | Java 沒裝 | 見 §5 |
| `Permission denied` / `not logged in` | Firebase 沒登入 | 跑 `npx firebase login` |
| `git push` 說 `rejected` | 別台電腦先推了新東西 | 先跑 `git pull --rebase` 再 `git push` |

## 10. 兩台電腦交替使用時的規矩

**每次開始工作前**，先把別台推上去的東西拉下來：

```bash
git pull
```

**每次結束工作前**，把這台的東西推上去：

```bash
git add -A && git commit -m "說明你改了什麼"
```

```bash
git push
```

> 忘記 pull 就開始改，之後 push 會被擋下來（`rejected`）。
> 那時候跑 `git pull --rebase` 再 `git push` 就好，不會弄丟東西。
