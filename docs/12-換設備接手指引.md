# 12｜換設備接手指引

> 給「換一台電腦繼續做這個專案」的人。假設你**完全沒設定過**這台新電腦。
> 每一步都寫了「會看到什麼」與「怎麼確認做對了」。
>
> 最後更新：2026-09-05（管理後台七項全完成＋場次改判＋挑戰攤位，見 `CLAUDE.md`）

**不需要搬資料夾。** 所有東西都在 GitHub 上，新電腦重新抓下來就好。
沒進版控的只有可以重新產生的東西（`node_modules`、測試產出、記錄檔），
以及**不該離開這台電腦的登入憑證**。

### 哪些東西不會跟著走

| 東西 | 在哪裡 | 新電腦怎麼辦 |
|---|---|---|
| `node_modules/` | 專案裡 | `npm ci` 重裝（§4）|
| `functions/engine/` | 專案裡 | `npm run sync:engine` 重新產生 |
| Firebase CLI 登入 | `~/.config/configstore/` | `npx firebase login` 重登（§6）|
| gcloud 憑證 | `%APPDATA%\gcloud\` | `gcloud auth application-default login`（§6）|
| Claude Code 登入 | 使用者目錄 | 第一次啟動時重登（§7）|
| `.claude/settings.local.json` | 專案裡（被忽略）| 不用搬，重新授權即可 |

**這個資料夾裡沒有任何密碼或金鑰檔**（已確認：沒有 `.env`、沒有
`serviceAccountKey*.json`）。密鑰一律在 Google Secret Manager，
不在程式碼裡（R-SEC-001）。

## 0. 離開舊電腦之前（1 分鐘）

在舊電腦的 VS Code 裡按 <kbd>Ctrl</kbd> + <kbd>`</kbd> 叫出終端機，貼上：

```bash
git status
```

**看到這一行就代表都存好了**：

```
nothing to commit, working tree clean
```

如果看到一堆檔案名稱，代表有東西還沒存。貼這兩行：

```bash
git add -A && git commit -m "wip: 換設備前存檔"
```

```bash
git push
```

接著**再確認一次真的推上去了**：

```bash
git log origin/demo..HEAD --oneline
```

**什麼都沒印出來就是對的**（代表本機沒有比 GitHub 多的東西）。
如果印出了幾行，那幾筆還沒上去，再跑一次 `git push`。

> ℹ️ `main` 分支落後 `demo` 很多是**正常的**。這個專案的規矩是
> 改動先進 demo 驗證，驗過才 merge 進 main（R-GIT-001）。
> 換電腦不用管 main。

## 1. 新電腦要先裝的三樣東西

2. 選 **LTS** 那顆綠色按鈕（版本要 **22 或更新**）

### ③ VS Code（寫程式的編輯器）

1. 開 <https://code.visualstudio.com/>
2. 下載、安裝、一路 Next


**要看到 `git version 2.` 開頭**。

## 2. 把專案抓下來

在同一個終端機裡，**一行一行貼、每行按 Enter**：

```bash
cd D:\
```

```bash
git clone https://github.com/msw2004727/toosterx-tournament.git
```

第一次可能會跳出一個視窗要你登入 GitHub，照著登入即可。

跑完會看到類似 `Resolving deltas: 100% ... done.`。接著：

```bash
cd toosterx-tournament
```

```bash
git checkout demo
```

**看到 `Switched to branch 'demo'` 就對了。**

> ⚠️ **一定要切到 `demo` 分支。** 這個專案的規矩是所有改動先進 demo 驗證，
> 驗過才 merge 進 main（`CLAUDE.md` 的 R-GIT-001）。

### ⚠️ 確認行尾是 LF（Windows 專屬，這件事出過事）

Windows 的 Git 預設會把檔案的行尾換成 CRLF。這個專案的變異測試用
**逐字的多行比對**，一旦變成 CRLF 就會有一半的變異變成「找不到程式碼」——
看起來像腳本壞了，其實是環境（R-SRC-002，2026-09-03 真的發生過）。

專案裡的 `.gitattributes` 已經釘死 LF，所以新電腦 clone 下來應該是對的。
**還是確認一次**，貼上：

```bash
node -e "const s=require('fs').readFileSync('firestore.rules','utf8');console.log(s.includes('\r\n')?'❌ 是 CRLF，要處理':'✅ LF，正確')"
```

**要看到 `✅ LF，正確`**。

如果看到 ❌ 才需要修。**修法會丟掉沒有 commit 的改動**，
所以先確認 `git status` 是乾淨的（剛 clone 完一定是），再一行一行貼：

```bash
git config --global core.autocrlf false
```

```bash
git rm --cached -r .
```

```bash
git reset --hard
```

跑完再用上面那一行檢查一次，要變成 ✅。

## 9. 常見狀況

| 你看到 | 意思 | 怎麼辦 |
|---|---|---|
| `'git' 不是內部或外部命令` | Git 沒裝好或沒重開視窗 | 關掉終端機重開；還不行就重開電腦 |
| `npm ci` 卡住很久 | 正常，第一次要下載很多東西 | 等它跑完，通常 1–3 分鐘 |
| 測試提到 `browserType.launch` | Playwright 瀏覽器沒裝 | `npx playwright install chromium` |
| 測試提到 `emulator` 或 `java` | Java 沒裝 | 見 §5 |
| `default Firebase app does not exist` | functions 的相依沒裝 | `npm ci --prefix functions` |
| `Permission denied` / `not logged in` | Firebase 沒登入 | `npx firebase login` |
| `Could not load the default credentials` | gcloud 沒登入 | `gcloud auth application-default login` |
| 「偵測到上一次變異測試的殘留」 | 上次變異測試被硬砍 | 照它說的做，它會自動還原（§8）|
| 一半的變異變成「找不到程式碼」 | 行尾變成 CRLF | 見 §2 的行尾檢查 |
| `git push` 說 `rejected` | 別台電腦先推了新東西 | `git pull --rebase` 再 `git push` |
| 網站沒有更新 | 瀏覽器還跑著舊的那一份 | **重新整理整頁**（只改網址列的 `#/...` 不會重新載入程式）|

## 10. 兩台電腦交替使用時的規矩

**每次開始工作前**，先把別台推上去的東西拉下來：

```bash
git pull
```

**每次結束工作前**，把這台的東西推上去：

```bash
git add -A && git commit -m "說明你改了什麼"
```

```bash
git push
```

> 忘記 pull 就開始改，之後 push 會被擋下來（`rejected`）。
> 那時候跑 `git pull --rebase` 再 `git push` 就好，不會弄丟東西。

## 11. 驗證網站的時候

demo 站是 <https://cup-demo.toosterx.com>。

**推版之後大約要等 1–2 分鐘** Cloudflare Pages 才會部署完。確認方法：

```bash
curl -s https://cup-demo.toosterx.com/js/config.js | grep -o "CACHE_VERSION = '[^']*'"
```

印出來的版號要跟本機一致（本機的看 `js/config.js` 最上面）。

> ⚠️ 版號對了但畫面還是舊的 → **整頁重新整理**（<kbd>Ctrl</kbd>+<kbd>R</kbd>）。
> 這個站是 hash 路由，只改網址後面的 `#/...` **不會**重新載入程式，
> Service Worker 也還抱著上一版的快取。這件事很容易誤判成「功能壞了」。
