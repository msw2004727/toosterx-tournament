# Demo 測試時間、檢錄與誤開賽復原

## 挑戰攤位測試

在 Demo 頂部點「測試時間」，選擇活動日期及時間後啟用。只有此瀏覽器分頁的挑戰活動使用該時間，兩小時後失效；重新載入保留選擇，關閉分頁即結束。可隨時點「恢復真實時間」。

抽獎頁籤、攤位是否開放、單日次數及 CSV 預選日期都依挑戰活動時間。登錄的 `recordedAtMs` 與 `activityDate` 為測試日期，`createdAt` 仍是伺服器時間。日期開關與日界線仍會驗證；正式站拒絕 `demoTestTime` 標記。

`config/env.env == demo` 且 `allowChallengeTestTime == true` 才能提交模擬紀錄。比賽時鐘、重複送出防護與作廢期限都使用真實伺服器時間。

## 資料未填齊的檢錄

已核准球員即使生日、身分證後四碼或背號未填齊，仍可現場確認並勾選出賽，計入已確認人數及完成檢錄門檻。「待補資料」保留為提示。標為「有問題」仍須先取消問題註記才能勾選。

身分資料修訂版本仍須一致；管理員後續修改生日／身分證資訊時，沿用原有重新檢錄流程。

## 誤開賽歸零

管理員到「我的 → 賽程管理」，選擇組別及已開打場次，点「覆核／改判 → 歸零並退回未開賽」，確認後填寫原因。

伺服器交易清空比分、半場比分、PK、時鐘、檢錄、出場名單與事件，退回 `scheduled/pre`，保留場次 ID、對戰、日期、開賽時間、場地與場次編號。舊資料、原因及操作者封存在稽核中；首頁看板同交易移除該場進行中紀錄，積分與晉級管線重新計算。

歸零增加 `resetRevision`，新的父文件寫入附唯一 `writeNonce`，事件／檢錄／出場名單附同一世代。舊裝置離線佇列不能把歸零後的比賽恢復為進行中。場次可正常重新檢錄與開賽。歸零需連線；未確認伺服器結果時不顯示成功。

## 日期驗收

- 10/10 僅開三攤：完成指定三攤即可取得當日一張抽獎券，10/9 的成績不能混入。
- 當日已有有效完整紀錄時，即使玩家彙總欄位尚未更新，仍顯示完成；離線快取尚未確認且不足時先顯示載入，不顯示未完成。
- CSV 依選取日期重新由伺服器查資格，內容與檔名皆含日期。
- 歸零後舊開賽、比分、事件與檢錄補傳須失敗；新世代重新開賽與記分須成功。
