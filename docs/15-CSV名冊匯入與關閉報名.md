# CSV 球隊名冊與關閉線上報名（2026-09-29）

主辦決定改由後台統一匯入名冊。匯入後直接核准並鎖定，可安排賽程。

## 跨盃賽參賽（2026-09-29 主辦調整）

三天為不同盃賽，主辦取消原規章「每人限報乙隊」的系統限制。
同一球員可出現在不同球隊名冊；同份 CSV、後續匯入、管理員補件及背景名冊更新均不以生日、後四碼或本人帳號跨隊退件。
不另加日期限制。同一球隊重複匯入、同隊已填背號重複仍檢查；CSV 每隊人數及資料完整度依主辦後續調整，不檢查年齡資格。
`REGISTRATION_LIMITS.onePlayerOneTeam` 及線上 `config/registration.onePlayerOneTeam` 均為 `false`。
部署須更新 `importTeamsCsv`、`updateMemberIdentity`、`onMemberWritten` 三支 Function；設定以 `scripts/set-registration.mjs --project PROJECT_ID --allow-multi-team` 更新並留下稽核。
此決議優先於早期文件中的每人一隊規定；舊退件稽核仍保留原始原因。

## CSV 每隊人數（2026-10-02 主辦調整）

管理員上傳的 CSV 名冊不受每隊 15 位球員上限限制。前端預覽及伺服器重新驗證採同一規則；匯入後的背景 trigger、重放及球員補件不會再以人數超限退件。
背景程序以球隊的 `source: 'csv'`、`captainUid: null` 與 `rosterLocked: true` 辨識管理員匯入名冊。一般客戶端建立球隊必須以自身帳號為隊長且未鎖定；隊長可以在草稿期轉移隊長帳號，但不能自行修改來源或鎖定名冊。因此豁免必須同時滿足這三項，單獨偽造 CSV 標記或清空隊長帳號都無法取得豁免。
一般線上報名仍遵守 15 人上限。整份 CSV 的容量、格式、重複隊名、背號及資料隱私檢查繼續有效。2026-10-07 主辦取消匯入的球員資料完整度及年齡資格限制，有填才檢查格式。
部署先更新 `onMemberWritten`，再更新 `importTeamsCsv`，最後發布前端，避免新名冊被舊版背景程序退件。

## 操作

1. LINE 登入 →「我的」→「匯入球隊名冊」，或在報名審核頁按「匯入 CSV 球隊名冊」。
2. 下載範本，一列一位球員，同組別與同隊名合併為同隊；也可只填組別與隊名建立零人球隊，不產生佔位球員。
3. 上傳 `.csv`，展開各隊預覽並修正所有錯誤。
4. 勾選已核對名冊及未成年使用暱稱，按「匯入並核准球隊」，確認後儲存。
5. 成功後到「賽程管理」抽籤、安排及發布賽程。

| 欄位 | 填法 |
|---|---|
| 組別代碼 | 使用匯入頁列出的代碼（例如 u6、u8、u10、women、adult-fun、adult-open） |
| 球隊名稱 | 必填，同組同隊名為同隊，不可與既有球隊重複 |
| 球隊簡稱 | 可留白，同隊有填時須一致 |
| 球員姓名或暱稱 | 可留空或省略欄位；未滿 18 歲填暱稱 |
| 背號 | 選填；可留空或省略欄位，多人留空不重複。有填為 0–999 整數，同隊不可重複（07 與 7、00 與 0 視為相同） |
| 出生日期 | 可留空後補；有填時用西元 YYYY-MM-DD，例如 2017-01-01 |
| 身分證後四碼 | 可留空後補；有填時為四位數字，保留開頭的 0，不收完整身分證 |
| 守門員 | 是／否，可留白（否） |
| 隊長 | 是／否，可留白（否），每隊最多一位場上隊長 |

Excel 請另存「CSV UTF-8（逗號分隔）」，生日及後四碼欄建議設定為文字。
也支援繁體中文 Big5 CSV、含 BOM 的 UTF-16 LE／BE CSV；預設自動辨識。
上傳後顯示讀取編碼，請核對中文。若文字不正確，可使用「CSV 文字編碼」選單重新解碼，不必重新選檔。
讀檔失敗、編碼錯誤、欄位內容錯誤會分別提示；不能把 `.xlsx` 直接改名為 `.csv`。
欄位也接受英文 key：divisionId、teamName、shortName、playerName、jerseyNo、birthDate、idLast4、isGoalkeeper、isCaptain。
每份上限 1 MB、100 隊、1,000 筆資料；CSV 匯入不限制每隊名額。只有組別與隊名必填，所有球員欄位都可留空或省略。有填日期須為有效西元 YYYY-MM-DD，不以年齡資格或賽事日期設定阻擋匯入。

## 儲存與權限

- 只新增球隊，不覆蓋或補入既有球隊；有任何錯誤整份不寫入。
- 伺服器在交易中重新驗證管理員身分、組別、已填資料格式、重複隊名及背號。
- 球隊、私密 members、公開 roster 與 team.import 稽核一次提交。
- 日期及後四碼只在 members；roster 沿用既有白名單投影，不存這些私密欄位。
- 同一球隊重送不會新增第二次，併發匯入也只會成功一次。
- CSV 建立的球隊不會冒用上傳者為隊長、不發邀請碼。
- 網路中斷後若結果不明，先查看球隊清單；再次提交不會覆蓋已建立資料。

## 後台補填與修改（2026-09-29）

主辦選擇：生日及身分證後四碼可先留空，球隊仍直接通過並可安排賽程。
從「查看球隊清單 → 已通過 → 展開球隊 → 補填資料／修改資料」開啟表單。
生日於後台以民國年月日輸入，保存時轉西元 ISO；身分證只收後四碼。
可分次補件，未知生日三格全留空；有填的資料仍須格式有效、符合年齡，允許與別隊球員的身分資料相同。
每次填修改原因，`updateMemberIdentity` 交易保存前後值、操作者、時間及原因。
若另一位管理員已修改，舊表單不得覆蓋；關閉表單後按「重新載入名單」。
待補球員不能勾出賽，Firestore rules 同時阻擋；補齊後在檢錄頁按「重新載入球員資料」。
修改會使已有檢錄結果失效、未開賽場次需重新確認；舊檢錄資料保留於本次稽核。
檢錄文件攜帶身分版本，離線舊畫面不能以舊證件資料通過新版檢錄。
私密欄位與補件旗標不進公開 roster。

### 背號留空與修改（2026-09-29）

- CSV 與後台表單都允許無背號；管理員可補填、修改、清空。不同球隊可用相同背號。
- 同隊已核准或待審名冊中的已填背號不得重複；修改自己的其他資料不會把自己的背號當成重複。
- 新匯入球員 ID 與背號分離且跨隊唯一；舊球員 ID 保留，改號不會新增、覆蓋或換掉球員。
- 同隊修改使用交易及版本鎖，併發搶同號只成功一位；所有修改保留稽核。
- 未開賽出場名單同步新背號，先發／替補與球員 ID 不變。已開賽陣容及事件保留歷史快照。
- 修改後重新檢錄，賽務頁重新載入最新名冊；沒有背號本身不阻擋檢錄，生日及後四碼仍須補齊並符合资格。
- 後端先部署，舊前端未送出背號欄位時保留既有背號。

### 報名審核修改隊員姓名（2026-10-04）

管理員／總管於「報名審核 → 展開球隊 → 隊員旁的編輯圖示」修改姓名／暱稱，
填寫修改原因後按「儲存資料」。姓名必填、最多 40 字，不含換行或控制字元。
未成年隊員沿用暱稱及既有隱私遮蔽規則；不提供變更 `nameKind` 的入口。
已通過 CSV 名冊可一次修改姓名、背號、生日與後四碼；其他既有名冊及隊職員提供僅更名表單。

`updateMemberIdentity` 在同一交易保存私密姓名、公開投影、射手榜顯示名、身分版本、
未開賽出場名單、檢錄失效及不可變更的前後值／操作者／時間／原因稽核。
球員 ID、報名狀態、名冊成員及歷史比賽事件不因更名而改變。
未開賽場次需重新檢錄；賽務頁重新載入名單後再核對。
其他管理員已修改姓名或版本時，舊表單不能覆蓋；同一操作重送以收據回覆，不重複修改及建立稽核。
儲存需連線；離線、伺服器拒絕及無法確認結果皆顯示原因並保留輸入，不顯示假成功。

### 公開球隊名單

組別的「球隊」直接監聽該組已核准球隊，不再依賴賽程或積分榜；尚未排賽程也會顯示，退出及未核准隊不列入。
空清單明示尚無已核准球隊，不宣稱「報名截止後公布」。讀取錯誤獨立提示，可重新載入。
球員公開名單取消五分鐘快取，重新進入即讀最新投影；讀取失敗不再假裝等待審核。

## 報名關閉

`config/registration` 使用 `open:false, hidden:true`。
一般使用者看不到報名入口；既有球隊仍可從「我的」查看公開資料。
舊 `/register`、`/register/new`、`/join/:code`、`/team/:id/manage` 連結顯示關閉說明。
正在開啟的報名頁會隨設定更新離開表單；Firestore rules 亦阻擋自助建隊、加入及修改。
管理員、檢錄與公開查詢權限照常。眼鏡切結書仍可供現場查閱及列印。

總管可在報名開關頁調整「關閉並隱藏線上報名」。重新開放須先取消隱藏，再開啟報名並設定有效日期。
部署腳本：`node scripts/set-registration.mjs --project PROJECT_ID --close --hide`，保留其他設定並新增稽核。

## 2026-09-29 編碼與讀檔修正

舊版將讀檔／CSV 驗證過程中的所有 TypeError 都誤標為 UTF-8 解碼失敗，且只收 UTF-8。
以真實 Big5 位元組重現相同提示後，新增 `js/lib/csv-file.js` 將讀檔、解碼、內容驗證分開。
支援 UTF-8（有／無 BOM）、Big5、UTF-16 LE／BE；有 BOM 時嚴格遵守標記，不將損壞的 UTF-8 猜成 Big5。
`Blob.arrayBuffer()` 不支援或失敗時改用 FileReader，真正的讀取錯誤會請使用者重新選檔。
損壞編碼、替代字元、改名的 Excel 活頁簿仍會阻擋；未放寬任何名冊資格與匯入權限。
