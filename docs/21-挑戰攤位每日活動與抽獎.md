# 挑戰攤位每日活動與抽獎

主辦 2026/10/05 指定：每日開放攤位分開設定，完成當日全部開放攤位取得當日一次抽獎機會。

- 「挑戰攤位登錄 → 選擇你的關卡」各卡片列出 10/9、10/10、10/11 的開放開關及每日完成的唯一玩家人數。指派攤位可設定自己負責的關卡，管理員可設定全部。
- 初次發布保留所有既有玩家與登錄紀錄，七個攤位三天均預設開放，之後由現場人員調整各日開關。
- 關閉的攤位不列入該日必需集章；當日零攤位開放時不發券。各日最多一張，重複登錄不增加張數。成績 0 分仍可完成一般計分關卡，現場簽到須符合既有完成門檻。
- 玩家首頁及我的挑戰卡共用日期頁籤和集章圈圈。台北時間活動前選 10/9，活動中跟隨當日，活動後保留 10/11；可手動查看其他日，跨午夜自動切到新當日。
- 日期採參與時刻 `recordedAtMs`；離線跨日補送仍屬原參與日期，不能因補送延遲被改到下一天。舊紀錄缺此欄位才採伺服器 `createdAt`，沒有時間則不猜日期。
- 資格以有效登錄紀錄及當日開放設定為依據。畫面、背景彙總與伺服器 CSV 共用 `js/engine/challenge-days.js`，不等待 `isBest` 或玩家背景彙總才顯示已完成。未同步的完整集章顯示「今日集章完成，待同步確認」；已儲存後立即顯示已取得資格。作廢最後一筆有效紀錄會撤銷該日資格。
- CSV 每次只匯出所選活動日，新增活動日期與當日開放關卡數，檔名包含該活動日。下載前在伺服器一致快照重新核對設定及有效紀錄，其他日期不混入。
- 開放設定採交易、舊狀態檢查與稽核；未指派、跨活動、停用帳號遭拒。登錄規則核對日期窗口、參與時間與當日開關，拒絕偽造日期及尚未到的參與時刻。

發布：先部署 Demo 的 `onAttemptWritten`、`updateChallengeDay`、`exportDailyDraw` 與 rules，發布網站，再執行 `scripts/release-challenge-days.mjs --dry-run`。確認指定提交與設定更新時間後 `--apply`，腳本先備份、初始化開關及每日彙總，全程不刪除或重設原資料。Demo 驗收完成後，同樣步驟發布正式環境。備份位於忽略版控的 `tools/challenge-days/backups/`。

驗收涵蓋三攤完成、跨日不混算、換日前後、活動前後頁籤、午夜自動切換、零攤位、重複、作廢、離線補送、0 分、背景彙總延遲、開关並發、權限及 CSV 日期。每日算法另有四條變異測試，確保跨日、開關與零攤位防線能抓到錯誤。
