## 執行器、CI 與證據

`node scripts/mutation-e2e.cjs` 執行全部 72；精確選測是 `node scripts/mutation-e2e.cjs --only E55` 或 `--only E55,E56`。一致性／稽核 runner 同樣支援精確 --only，但需先由 demo Emulator 啟動。未知／重複 ID、缺映射／缺預期斷言、零測試、跳過、改變測試集合、缺／壞 JSON、重試、啟動失敗、signal、中止、程序／整個 test 逾時、無關 setup／teardown／斷言全分類為異常，不能算抓到。預先指定的 expect 等待斷言逾時可算有效證據。每條最多 3 分鐘（E2E）／2 分鐘（Jest），retries:0。

同一測試集合只在同輪相同 source hash／Node／browser／port 配置重用已通過的正常基準。子程序使用 argv、stdout／stderr 串流寫檔；每條有獨立 JSON、完整指令／cwd、退出碼／signal／耗時、分類與必要 trace／截圖。POSIX／Windows 只清理當次建立的子程序樹。UUID＋PID 排他鎖不能覆蓋有效鎖，備份實際 bytes，原子檔案替換並還原原有未提交內容；合法內部 token 才能通過 guard。強制 kill／runner 取消時不能保證 finally／artifact 已完成，殘留 guard 會保守拒絕下一輪，不假裝一定保證產物。

Unit／Functions／Rules 舊 431 條變異仍保留原先「非零即 caught」判定，**其結果不能等同新版每條由預期缺陷斷言抓到的證明**。只共用安全鎖、實際內容備份與原子還原；完整 CI 相容性驗證由最終 PR head 執行。新 32 條與舊 12 條稽核重驗使用嚴格分類。

CI 拆成一般 E2E 與 E2E mutations。完整一般 E2E 保留所有三個 Chromium 視窗；變異保留原先 chromium-mobile 覆蓋，不做同 checkout 並行注入。與歷史相同的 Ubuntu 24.04／Node 22.23.2＋lockfile 的 Playwright 1.62.1／Chromium 1234（Chrome 151.0.7922.34），CI 禁止暗中切系統 Chrome。Emulator CI 維持已驗證的 Java 17；本機 Node 22.23.3／Java 25，Storage 的 Unsafe warning 沒被當成成功／失敗證據。每個 job 和主要測試 step 有時限，checkout 明確指定 PR head SHA；刻意併發／交易 retry 的個別案例最多 20 秒，整個 test 逾時仍判異常；變異 JSON／logs／trace／screenshots always 上傳保留 14 天。未以 continue-on-error、跳測或取消發布 workflow 換取綠燈。

推送前重新核對 main／demo 都仍為 `2b7361c`。專案文件與該 SHA 的實際 Cloudflare check-runs 相符：feda-cup 的 main 成功為 production、demo 有 `demo.feda-cup.pages.dev` branch preview；feda-cup-demo 的 demo 為 production、main 有 `main.feda-cup-demo.pages.dev` preview。沒有登入 Cloudflare 帳戶直接讀設定，證據來自 GitHub 部署紀錄與 [Pages branch controls](https://developers.cloudflare.com/pages/configuration/branch-build-controls/)。僅推新 codex 分支並開以 demo 為 base 的 PR，不更新 production branch。預覽 hostname 依現有 firebase-config 會連 **demo Firebase**，沒有獨立資料隔離，不在 preview 做真資料操作。

待批准的 demo 操作順序：

1. 保存目前 demo 的 Pages deployment ID、Functions／Rules／indexes／Storage rules 版本，核對新查詢索引及 Storage 跨服務權限。通知管理員暫停所有管理變更（含人工名次裁定），先同步完 staff 離線佇列；本次不修改真資料。新 setManualRanking 要求 expectedVersion，過渡時舊前端的裁定請求會明確拒絕；不能把部署先後間的這個窗口宣稱完全無中斷。
