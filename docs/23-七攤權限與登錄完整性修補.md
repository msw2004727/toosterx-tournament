# 七攤權限、登錄與完整名單修補

## 完成行為

挑戰攤位、報到、裁判、記錄台與賽務員需啟用並指派至本活動的目標攤位；啟用的管理員／大總管可操作全部七攤。未指派、跨活動、停用、一般玩家與隊長不能登錄。所有角色仍受當日開放、成績範圍及資料完整性限制。

逐球型核對球數、每球選項與加總；次數必須整數；頭球只能登錄設定級距。主辦確認最高260cm，現有100–220cm保留，新增225、230、235、240、245、250、255、260cm。零分只要符合攤位規格就是有效參與，不轉成空白。

原始成績限制工作人員讀取；玩家讀取伺服器產出的 `attemptPublic` 白名單投影，沒有工作人員 UID、裝置識別、電話或作廢原因。成績路徑 ID 為權威，payload 不能覆蓋；新增成績必須指向已存在玩家且活動一致，不能預設最佳或作廢旗標。客戶端後續只允許作廢，工作人員仍受本人、指派及10分鐘限制；管理者可跨此時間作廢，不能直接改原始分數。異常历史值保留原件，排除於有效榜單與資格，另留私人的檢核紀錄。

送出不阻塞離線操作，但只有伺服器確認才顯示成功。待同步、儲存失敗與成功分開；離線玩家頁保留上次集章資料，資格顯示待確認，不把待同步成績當已入庫。已關閉日期的補送仍按現有政策拒絕，不擅自繞過開放條件。

「匯出資料」保留抽獎名單，新增完整挑戰名單及逐筆成績明細。可選活動日期、全部領卡／所選日有登錄紀錄。完整名單包含卡號、暱稱、玩家LINE UID、建立／綁定方式、七攤有效成績及狀態、可空電話、完成數與當日資格；沒有LINE／電話留空。狀態區分未參與、沒有有效成績、當日關閉；作廢紀錄可由明細追查。UID由私人users映射取得，不能用staffUid充當參與者UID。僅啟用的管理員／大總管在一致交易快照讀取並留下匯出稽核。CSV沿用BOM、引號／換行及公式注入防護。

每日開關由伺服器交易留下 `challengeRefreshJobs`。重算分批且保存進度，每位玩家使用當下設定與有效成績的交易快照。觸發器失敗重試可接續，重放不重複完成稽核。畫面與匯出持續從有效成績計算，不依賴尚未完成的摘要。

## 施工階段、步驟與做法

1. 從最新main建立修補分支，保留先前首頁統計與所有既有功能。正式與Demo先唯讀備份七攤、卡號、原始成績、私人UID映射、聯繫方式、排行榜及獎勵設定。以實際路徑ID對帳，異常清單另存，不猜測或替換成績。
2. 共享引擎加入成績形狀驗證，同步至Functions；規則阻擋非法新登錄。管線排除不合法歷史值、以實際文件ID更新最佳旗標，公開投影只拷貝明確白名單。補齊頭球級距，保留其餘計分設定與每日開放安排。
3. 加入耐久資格重算、完整名單伺服器接口与管理頁控制；保留既有抽獎出口。修正攤位及玩家離線狀態，使成功必須有伺服器確認。
4. 先隔離規則／Functions驗證，再瀏覽器回歸；固定提交与快取版本，Demo完成實際部署驗收後發布正式。所有私密備份與驗收檔放在未納入版控及Hosting的tools目錄。

## 驗收步驟

- 七種工作身分×七攤49組合法登錄回讀，以及未指派、跨活動、停用、玩家／未登入拒絕。
- 偽造逐球總分、漏球、非法選項、非整數次數、非法頭球級距、260cm合法值、錯誤活動／路徑ID、不存在卡號與最佳旗標均驗證。
- 七攤有效紀錄取得當日一次資格；重複不加張數，作廢最後有效紀錄撤回，零分保留，中醫不排名。
- 完整名單包含未全破與未參與者，篩選及日期不混算，玩家UID與聯繫方式關聯正確；未綁定／未填為空。明細含作廢及逐球，BOM与公式防護驗證。未授權匯出與讀私人成績拒絕，公開投影不含UID／電話。
- 開關後耐久工作完成，摘要、畫面與匯出一致；重放、並發與續跑不覆蓋較新設定。不把尚未同步或未確認快取算成已完成資格。
- 既有單元／規則與七攤瀏覽器回歸完成；逐字檢查候選差異、變異測試錨點、版本和共享引擎一致性。正式以唯讀資產、實際部署來源、Function狀態、設定與資料對帳驗收，不寫測試成績至正式庫。

## 部署步驟與做法

1. `scripts/sync-engine.js`，通過驗收後bump版本，提交固定候選；再次fetch確認main未前進，有前進則整合並重驗改動。
2. 先Demo、再正式，分別部署 `onAttemptWritten`、`updateChallengeDay`、`exportDailyDraw`、`exportChallengeParticipants`、`onChallengeRefreshRequested`。不部署無關的賽事、隊伍、統計或挑戰領卡函式。
3. 對指定專案執行 `node scripts/release-challenge-integrity.mjs --project=<project> --backup=<tools私密路徑>` 唯讀備份／dry-run。核對數量及異常清單後，以相同參數加 `--apply`，核對備份候選一致；逐筆交易讀當下原始資料產出安全投影、延伸頭球級距、重算有效資格。等待耐久工作完成，不刪卡、不重設成績、不覆寫並發新增紀錄。
4. 發布相容網站至該站分支；核對線上資產与候選hash，玩家頁能讀安全投影，管理頁完整匯出可使用。網站更新後部署相同候選 `firestore:rules` 收緊原始成績讀取／寫入。確認private拒絕與public可讀，Demo合成測試紀錄明確標記並清理；正式不以虛構參與者驗收。
5. 回讀函式來源／ACTIVE狀態、正式規則、七攤開放與頭球設定、公開投影隱私，以及完整名單與原始有效成績對帳。保存版本、SHA、測試結果、備份與線上證據。

## 回復

保留原始資料及備份，網站問題優先作相容的前端熱修；不能為回復舊版而重新公開原始UID。保留新公開投影與私密讀取邊界。級距回復或資格重算只能針對已核對的設定版本進行，不能回蓋活動期間新資料；任何資料修復都有稽核。若匯出故障，停用該入口並保留既有抽獎流程，修復後再驗收。
