# 首頁瀏覽與分享統計

首頁標題卡右下角呈現即時在線、累計瀏覽及分享數。手機採內容下方靠右排列，寬螢幕放在卡片右下角空白處。附「含活動加成」及各欄位說明，明確區分實際統計與活動展示值。

- 即時在線＝當下有可見首頁、90 秒內仍有心跳的不同瀏覽器識別數＋33。30 秒更新一次；同瀏覽器多個頁籤只計一次；關頁／隱藏會嘗試立即退場，未送達則到期移除。這是可見首頁在線裝置統計，不是驗證過的真人數或全站其他頁面的在線數。
- 累計瀏覽＝從本功能上線起實際登錄的首頁開啟次數＋33。重新整理／重新進首頁是新一次；同一次心跳、重試、首頁資料重畫及切頁籤不增加。既有網站沒有歷史瀏覽計數，不能回補歷史真實瀏覽。
- 分享數是活動展示值，從固定上線起算時間 33 開始，每完整 10 分鐘＋6，在台灣時間 2026/10/12 00:00 凍結。由固定時間公式計算，沒有每十分鐘寫庫或 cron；重新整理／重新部署不重設起算。它不是實際社群分享次數，欄位提示明確說明。
- 入庫資料只保存實際瀏覽計數、隨機瀏覽識別的雜湊、短期在線狀態及起算設定；不記錄 LINE UID、IP、暱稱或電話。僅 callable 回傳聚合結果；三個內部集合都不開放客戶端直接讀寫。匿名公開訪客可以被計入，不需額外登入。
- 計數從後端回傳，客戶端不能指定總數、加成、起算時間或服務時間。分享在兩次後端回應之間用單調時鐘推進，避免手機時區或時鐘更動影響結果。連線失敗不捏造在線數；已同步的累計值保留，離線在線顯示「—」。

## 施工階段、步驟與做法

1. 新增共享時間／加成引擎、伺服器 `reportHomeMetrics`、私人的 homeMetrics／homeVisits／homePresence。交易記錄 visit receipt，首次可見開啟才增計數；重試原 visit 不重複；每次 heartbeat 用 sequence 防止較舊請求覆蓋離場狀態。
2. 在首頁建立獨立計數元件，資料重畫只移動既有元件，不重新建計數工作。visibilitychange、online／offline、pagehide 與路由清理管理心跳生命週期；分享只更新數字節點。
3. 確認不同寬度與主題不遮蔽原標題／日期。私人的真實資料與顯示加成分開，日期截止採 +08:00 明確時區。

## 驗收

- 引擎測起算前、599999／600000 毫秒、午夜截止及截止後長時間。
- Firestore Emulator 測首次、重試、並發同 visit、跨頁籤去重、不同瀏覽器、離場乱序、90 秒到期、偽造欄位拒絕、缺設定無寫入、設定時間不重設與聚合輸出隱私。
- 同版 rules 測未登入及管理員皆不能直接改計數／讀取私人識別。
- 手機瀏覽器測三項數值與說明、頁面重畫不計次、刷新同 visitor／新 visit、跨午夜、斷線恢復、換頁停止，以及 320／480／739／1280px 深淺主題幾何和截圖。
- 上線後回讀函式與來源、比對發布檔案 hash，查初始化時間；用首頁正常訪問驗證回傳計數與伺服器實際資料。正式驗收訪問本身會如實被計入，不手動減除。

## 部署

先 sync-engine 及通過相關測試，固定候選提交和版本。先部署 Demo 的 `functions:reportHomeMetrics`，執行 `scripts/init-home-metrics.mjs --project=feda-cup-demo` dry-run，再同指令加 `--apply` 初始化；上 Demo 網站，驗證函式、UI、計數及時程。

Demo 通過後部署正式相同函式，對 `feda-cup-2026` dry-run／apply 初始化，發布同一候選網站。預設 apply 當時為上線起算時間；可用明確 `--start=2026-10-09T00:00:00+08:00` 指定主辦授權的其他起算時間。既有 settings 存在時原樣保留，不能利用重新部署歸零真實計數或重設展示時程。只部署新增函式，不重新部署與本功能無關的既有比賽／挑戰函式或規則。

確認 origin/main 未前進、快取版本一致、候選差異與正式資產一致；發布紀錄保留實際設定的台灣時間及 UTC 時間、提交、Demo／正式回讀和測試結果。回復網站舊版會隱藏這個功能；停用新 callable 只影響統計。保留真實瀏覽與起算設定，復原時不重算或刪除既有資料。
