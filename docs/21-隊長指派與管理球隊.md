# 隊長指派與管理球隊（2026-10-08）

「我的」新增有底色的「管理球隊」功能按鈕（`#/my/teams`）。管理員與大總管可查看全部球隊；隊長只查詢 `captainUid` 等於自己的球隊。依組別收折，再點擊球隊展開私密名冊。

身分授權頁維持大總管專屬。展開用戶後以「組別 → 球隊」兩層下拉選單指派隊長，支援更換與撤銷。隊長不是全站 staff 角色，指派不會新增其他工作人員權限。每隊一位隊長，同一用戶可管理多隊；指派與撤銷即時反映在「我的」。

管理球隊與報名審核共用 `team-roster.js`、既有隊名與球員修改表單。可修改隊名／簡稱、隊員姓名／暱稱，以及已核准 CSV 隊員的 0–999 背號、生日與身分證後四碼；生日使用民國年表單。資格檢查、同隊重號、修改原因、版本衝突、公開投影、檢錄失效與修改稽核沿用原有交易。保留最新版的修改收據與重送防護。

`teams/{teamId}.managementLocked` 是獨立管理鎖，缺少此欄位視為未上鎖。只有管理員／大總管可單隊上鎖或解鎖，亦可一鍵全鎖／全解目前賽事的全部球隊。上鎖不改 `status`、`rosterLocked` 或參賽資格；鎖定時隊長可讀但不能修改，管理員／大總管仍可編輯。批次變更與稽核同一交易提交；超過 450 支需變更的球隊時整批拒絕，不留下部分成功。

後端新增 `assignTeamCaptain`（大總管）與 `setTeamManagementLock`（管理員／大總管）。既有 `updateMemberIdentity` 與 `updateTeamName` 在交易內驗證最新隊長、鎖定狀態與身分，避免開啟舊表單後繞過撤銷或上鎖。Firestore rules 亦阻擋鎖定後的舊報名入口直接寫入。

部署包含前端、上述兩個新 callable、更新的 `updateMemberIdentity`、`updateTeamName` 與 Firestore rules。規則與函式各自部署，先 Demo 驗證，再以同一提交更新正式環境。版本 `0.20261008` 由 bump 腳本同步，新增前端模組列入 Service Worker 離線清單。

已驗證 1,466 個單元測試、277 個 Functions 交易測試、281 個 Firestore rules 測試，以及 11 個測試工具案例。新增的五個 Functions 反向測試與一個 rules 反向測試全部抓到預期錯誤，還原後完整後端測試再次通過。瀏覽器測試涵蓋手機、桌機、320px、隊長指派／撤銷、私密名冊邊界、共用表單與單隊／批次鎖定。
