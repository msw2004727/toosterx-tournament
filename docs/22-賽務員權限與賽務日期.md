# 賽務員權限與賽務日期（2026-10-08）

## 需求與完成行為

新增角色 `staff`（賽務員），保留既有記錄員。總管在「身分授權」選人、選賽務員，再選負責場地；不選場地代表全部場地。使用者在「我的」按「更新權限」，即可看到賽務台入口，不必登出重登。

賽務員可檢錄、讀取檢錄個資、編輯出場名單、控制時鐘、記分與事件、送出完賽、在既有期限內自撤回。進行中場次的時間與事件修正沿用原本的交易、版本檢查、操作回執與稽核。賽務員不具備身分指派、球隊管理、賽程管理、強制檢錄、覆核、重開及改判權限。管理員與總管看全部場地。

首頁以 `EVENT.dates` 和 `EVENT.timezone` 選日期，不再以舊 `assignment.date` 綁定首頁。這是顯示方式調整，不需批次改動現有 staff 文件。活動前選首日，活動期間依台北當天，活動後選末日。本次活動對應 10/9 前及當日選 10/9，10/10 選 10/10，10/11 起選 10/11。

日期頁籤可手動切換活動三日。手動模式不因跨午夜被覆蓋，同一個分頁與帳號內往返檢錄、出場名單、LIVE、重新整理仍保留選擇；「跟隨今日」清除手動選擇並恢復自動模式。自動模式在午夜、手機回到前景、視窗取得焦點時重新核對日期。切換日期只保留一個場次監聽，不顯示前一日殘留場次。

## 施工階段、步驟與做法

### 第一階段：角色與授權

1. 以正式分支的已部署版本建立 `codex/staff-console-dates-20261008`，沿用獨立 checkout，保留原始工作目錄既有修改。
2. 在 `js/config.js` 增加角色字典 `staff`、顯示 level 2.5；繼承鏈放在記錄員與管理員之間，賽務員的操作權限與記錄員一致。FC 的六個既有角色不改。
3. 身分授權的角色選單由 `ASSIGNABLE_ROLES` 自動取得新角色。更新畫面說明，保留總管不可由介面指派、停用保留歷史的設計。
4. 更新 Firestore 的身分白名單及 scorer/referee/checkin/booth 粗粒度判斷；更新 Storage 的角色與原圖讀取白名單，以及 Functions 的時鐘、事件、挑戰日期與聯絡方式處理。場地範圍與管理操作的限制沿用原防線。
5. 保留身分載入時僅接受 active 文件的既有防線；`can`、`myPerms`、`myRoles` 與 `hasRole` 因此只取有效身分。新增賽務路由守衛確認 `staff.access`，停用或未授權者顯示原因，並補回歸與變異驗證。

### 第二階段：日期與賽務首頁

1. 新增純函式 `js/engine/staff-date.js`，由呼叫端傳入校正後時間、活動日期與時區。活動日期排序後夾在首末日之間；有效手動日期優先。
2. 新增 `date-selection.js`，用活動 ID 與 UID 組成 sessionStorage key，僅儲存手動顯示選擇，不存個資或權限。儲存被瀏覽器阻擋時退回記憶體，不阻止切換。
3. 首頁新增三個日期頁籤與「跟隨今日」，依自動或手動模式標示場次清單標題。選日期後先取消舊監聽，清空舊結果，再訂閱指定日期；用 generation 防止過期回呼覆蓋新日期。
4. 使用可清除的 timeout 核對日期，並監聽 visibility/focus。離開頁面時回收 timeout、事件監聽、Auth/同步回呼及場次監聽。
5. 「我的」與賽務首頁提供「更新權限」，重讀有效身分與權限矩陣。更新期間停用該按鈕，失敗明示原因。

### 第三階段：回歸與版本

1. 補日期邊界與賽務員權限單元測試；補 Rules 的指派場地、停用、禁止提權與管理操作測試；補 Functions 時間與事件修正測試。
2. 補瀏覽器測試：既有指派日期不蓋掉新預設、跨午夜、手動保留、回到 LIVE 再返回、跟隨今日、監聽回收、320px、管理員所有場地、登入後新增指派與停用。
3. 舊測試用明確時鐘表示測試日期，不再靠 assignment.date 選首頁。同步角色、權限數量與變異錨點。
4. 使用 `node scripts/bump-version.js` 更新版號與離線模組清單，確保新增模組納入離線資源。

## 驗收

必須完整跑 unit、Functions、Firestore Rules、Storage Rules、E2E 三種寬度、tooling 及變異錨點檢查；目標測試僅用於定位失敗。新變異需證實首末日、台北午夜、手動選擇、停用身分、舊監聽回收、Functions 賽務員角色與 Rules 記分授權均有鑑別力。

人工驗收流程：總管指派賽務員與 A 場 → 人員在「我的」更新權限 → 開賽務台 → 逐日切換且只能看到 A 場 → 進檢錄與 LIVE 後返回仍保留日期 → 跟隨今日恢復自動 → 管理員確認所有場地 → 停用後重讀權限，前端無操作入口且後端拒絕寫入。上線驗證另比對 HTTP 實際模組與待發布 commit。

6. 若需回復，以此次發布前 commit 部署相同四支 Functions、兩種 Rules 與前端；先停用新賽務員身分或改成既有記錄員，避免舊版認不出 `staff`。本次不涉及球隊、球員與比賽資料遷移。
