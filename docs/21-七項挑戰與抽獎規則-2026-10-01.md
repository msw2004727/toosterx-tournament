# 七項挑戰與抽獎規則（2026-10-01）

主辦要求保留原有五關，新增「中醫問診」與「一球三桶」，七項全部完成才有一次抽獎機會，完成後直接發布上線。

- 中醫問診：到現場向工作人員出示同一張挑戰卡 QR，由人員確認簽到打卡即可集章。不計分、不排名，不收集問診內容。
- 一球三桶：三個標桶緊密並排，每球一腳推射，三桶全倒才記成功。依提供圖片的三球排名規則，每輪三球記錄成功／失敗，成績為全倒次數 0–3，排名取最佳一輪。沿用完成體驗即可集章的認定，零次成功仍可完成。
- 抽獎：七個指定項目全數完成，每人一次。重複或未知項目不能湊數。作廢後若不再完成全部必要項目，資格回到零。

## UI

公開首頁與領卡頁說明七項規則。挑戰首頁展示七個不同 SVG 圖示、項目說明、七格集章進度、還差幾項及 QR 入口。我的挑戰卡保留大字代號與黑白 QR，以後端結算值顯示資格。中醫使用確認簽到按鈕；一球三桶逐球選「失敗／三桶全倒」，三球選完才能送出。

尚未同步或新規則尚未結算時不顯示舊規則的有效張數。中醫項目頁只顯示簽到流程，不顯示排行榜。320px、手機與桌面及淺深色主題均需檢查。

## 後端與發布

`drawEntries` 對 `allChallengesCompleted` 以 `requiredChallengeIds` 的完整集合判定資格，保留舊模式以支援後端先行部署的過渡。完成清單、張數及 `luckyDrawRuleVersion` 在玩家交易中提交，交易內讀抽獎設定，避免切換規則時舊結算覆寫新結果。CSV 只使用後端結算張數，且排除未經目前規則版本結算的玩家。

`scripts/release-seven-challenges.mjs` 限定兩個已授權 Firebase 專案，先 dry-run，備份原設定與衍生資格，再對指定且乾淨的已驗證提交 apply。兩個新項目、抽獎設定、稽核與發布收據同一交易提交；既有項目代碼衝突或設定更新時間改變時拒絕覆蓋。設定發布可重跑，逐玩家交易重算只更新衍生資格欄位，保留原完成清單、所有成績與其他資料，每次變更留 before/after 與原因。

流程依序為：完整測試與 CI → demo 後端／Rules → demo 新設定與資格重算 → demo 前端驗證 → 正式後端／Rules → 正式新設定與資格重算 → main 前端發布 → 真實站台讀取與資源驗證。工作人員指派由原有身分授權頁維護，不擅自新增帳號或放寬角色。

此次正式發布亦包含已在 demo 通過完整 CI 的 PR #2 一致性修正，因本次功能基於該版本開發。原始 `codex/prelaunch-audit` 工作區的未提交修改保留。

回復資訊包含發布前設定、資格衍生欄位與後端來源 ZIP，存於本機忽略的 `tools/release-seven-20261001`。回復不能刪除已收集的玩家成績或稽核；應先核對發布後是否有新的參與紀錄，再回復設定並重新結算。

## 攤位 SOP 修正（2026-10-01）

總管原本只能指派身分與場地，`buildStaffDoc` 把 `challengeIds` 清成空陣列，導致正式指派的攤位人員無法登錄。現在身分授權會載入關卡設定，提供多選攤位；挑戰攤位身分至少選一關，重新編輯保留既有指派，稽核記錄也包含關卡清單。管理員與總管仍可操作所有攤位，其餘人員受活動及關卡範圍限制；Firestore 同時守住跨活動寫入。

操作順序：人員先用 LINE 登入一次 → 總管在「我的／身分授權」選人員、身分與攤位 → 人員從「FEDA CUP 挑戰區／攤位登錄」按「更新權限」 → 多攤位人員先選攤位 → 開啟相機或輸入 `FEDA-0182`／`0182` → 核對玩家姓名與卡號 → 登錄三球細項或到場簽到。切換攤位會回收原頁監聽，不沿用前一個玩家的成績或聯絡輸入。

舊掃碼只支援 `BarcodeDetector`，沒有內建辨識的瀏覽器連入口都不顯示。現在相機入口固定可見，不可開相機時顯示原因與手動備援。可使用相機的瀏覽器優先使用原生辨識，否則使用隨站離線快取的 jsQR 1.4.0；只在裝置解碼，不上傳影像。掃碼視窗會在取消、離頁、切換到背景或成功後停止串流，也處理取消後才取得權限的晚回傳。QR 經過登入時保留關卡與卡號。

jsQR 來源為 npm `jsqr@1.4.0`，套件 SHA512：`dxLob7q65Xg2DvstYkRpkYtmKm2sPJ9oFhrhmudT1dZvNFFTlroai3AWSpLey/w5vMcLBXRgOJsbXpdN9HzU/A==`。保留 MIT 授權於 `js/lib/vendor/jsqr.LICENSE`，只增加本機 CommonJS → ESM 包裝。API 依 [官方 jsQR 文件](https://github.com/cozmo/jsQR) 及 [MDN 相機 API](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) 核對。

各攤位先確認待同步佇列送達，活動结束後由管理員或總管進入「我的／匯出資料」更新預覽與下載 CSV。下載前強制從伺服器重新讀取玩家、聯絡方式與規則；離線讀取失敗不下載快取名單。七項模式只收目前規則版本、七個指定項目全完成且權威張數為一的玩家，不在前端重新配券。CSV 保留 BOM、CRLF 與公式防護，匯出留下稽核。

七項展示文字由 `scripts/release-booth-metadata.mjs` dry-run 保存既有文件、更新時間與精確提交，再 apply。交易只准展示欄位，設定變動則停止，發布收據支持安全重試。原項目 ID、計分政策、統計、抽獎設定、玩家、成績与授權文件均不重設；本次備份與驗證證據在忽略的 `tools/release-booth-sop-20261001`。
