# 管理球隊新增球員

需求：在編輯球隊名稱旁新增球員入口。彈窗只有姓名／暱稱必填，背號、生日、證件後四碼、守門員、場上隊長可留空或不勾選；用加號增加多位球員，支援移除誤加的列。介面遵循組別色、深淺主題及 320px 最小寬度。

## 施工階段與步驟

1. 從已發布 main 建立 `codex/team-player-add-20261008`，在既有獨立 checkout 施工，保留原目錄未提交修改。
2. 新增共享 `team-player-add` 引擎：姓名必填，其餘可空；有填的背號、生日、後四碼仍需有效，擋同批與既有有效球員的同名、同背號及多位場上隊長。一次最多 50 人以控制單次交易容量。
3. 新增 `addTeamPlayers` callable：重讀當前管理身分、隊長指派及球隊管理鎖；管理員／大總管可操作，隊長僅限自己的未上鎖球隊。保留既有一般球隊人數限制與行政匯入名冊例外，避免成功回覆後被 roster cap trigger 退件。
4. 新增彈窗：姓名和背號置於首列，其餘資料收折；加列不重建輸入值，移除列重新編號，儲存期間停用操作，支援焦點循環、Escape 及路由離開清理。移除按鈕預留 44px 點擊範圍，與姓名／背號標籤保持間距，最窄螢幕也不重疊。
5. 更新管理球隊工具列與成功回呼：一次新增後展開該隊，重新讀私密名冊，顯示確認成功的人數。

## 做法與資料規則

伺服器只採用白名單球員欄位，角色固定 player、狀態 approved。沿用行政匯入名冊的 source csv，並以 createdVia team-management 區分手動新增，以保留既有補件與檢錄流程。生日在 UI 用民國年，存成西元 ISO；未提供的生日／後四碼為空字串，背號為 null，絕不轉成 0。

同一交易新增私密 members、以權威 privacy 引擎產生的公開 roster、更新球隊人數與 rosterRevision、新增 audits 與 managementOperations。會員 ID 由賽事、球隊、操作 ID、列序決定，不覆蓋既有成員。相同操作重送回同一回執，換人或內容重用 ID 拒絕。未滿 18 歲並填了生日者依介面提示使用暱稱；年齡未知的姓名仍使用既有遮蔽規則，照片不公開。原球隊審核狀態、管理鎖與賽程均不改。

## 驗收

- Unit：姓名單填、空值、背號 0、日期與後四碼、重複球員／背號／隊長、欄位白名單。
- Functions Emulator：管理員／總管／隊長、跨隊與停用拒絕、上鎖、整批原子性、並發搶背號、人數上限、行政名冊例外、重送與回執、原球員保留、公開投影無生日及後四碼。
- E2E：按鈕位置、單填姓名、加列與移除、選填資料、離線阻擋、錯誤保留輸入、不完整回覆不假成功、重送不重複、換頁清理、深淺色與手機／桌機／320px；明確檢查移除按鈕不覆蓋姓名／背號標籤。
- 完整 suite 與既有規則回歸通過；新增變異需抓到姓名必填失效、上鎖／跨隊授權被移除、公開投影漏建、回執檢查被移除及加列無效等缺陷。

## 佈署

1. 由 bump-version.js 更新版本及離線模組清單，檢查 diff、引擎同步及變異守衛，提交限定範圍的修改。
2. 先將同一 commit 送 Demo；單獨部署 Demo addTeamPlayers callable，待 Pages 更新，實測 Demo 的多位新增與回執，並清除專用驗收球隊／帳號。
3. Demo 驗收後，先單獨部署正式 addTeamPlayers，再快轉 main 發布前端；本次未修改 Firestore／Storage 規則，不重複部署未修改服務。
4. 對兩站核對 HTTP 版本和變更模組，未登入呼叫應被拒絕；正式站只作唯讀驗證，不用正式球員資料做新增試驗。
5. 回復時以前一 commit 的前端發布；新增 callable 可保留但 UI 不再呼叫，既有已新增名冊不能刪除或回滾。需要退回球員時依管理流程留下紀錄。
