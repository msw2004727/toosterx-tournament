# 紅黃牌統計與殘留資料修復（2026-09-30）

## 查證

正式環境現存 4 支球隊、0 場比賽、0 份積分榜；`boards/fairplay` 卻仍有 3 筆舊隊伍紀錄，`boards/scorers` 也有 4 筆同來源紀錄。三個舊隊伍 ID 均已不存在。這是公開看板未重建的殘留，並非現存球隊的紀律紀錄。

舊流程在場次刪除時直接退出、只於「變為完賽」時重建、球隊刪除只維護隊長建隊數、完賽後事件修正只對帳。紀律看板還直接合併各階段積分榜，可能重複球隊，且淘汰賽沒有積分榜，因此漏計。

## 新顯示與統計規則

- 公開分頁改稱「紅黃牌統計」，按組別分區，維持固定組別色，不再用序號暗示賽事名次。
- 每隊在所屬組別一列：完整隊名、已完賽場次、黃牌張數、紅牌張數、紀律扣分。扣分不是比賽積分；運動精神獎由主辦評選。
- 從現存有效完賽場次（finished／confirmed／walkover）與未作廢的事件計算，包含小組賽及淘汰賽。尚未出賽不列入。任一參賽球隊不存在或移組時，該場不作為看板有效來源。
- 同球員同場的扣分規則不變：黃牌 −1、兩黃換紅 −3、直接紅牌 −4、黃牌後直接紅牌 −5；不重複扣分。牌數顯示含第二張黃牌，紅牌含兩黃換紅，並另註兩黃換紅次數。規則文字讀取後端隨看板公布的 `scoringRules`。
- 全部組別不再被前端總共截成 20 筆；射手榜原本限制維持。
- 無有效資料與讀取失敗使用不同提示。觸發器更新期間，公開端也會核對球隊是否存在、組別是否相同，防止連到已不存在球隊。

## 防止再次殘留

場次刪除、重開、結果變動、球隊刪除／更名／移組，以及完賽後事件補登或作廢，均會重建相關組別。場次、事件、球隊、公開名冊及看板在同一交易內讀寫，避免舊重算較晚完成而覆蓋新資料。重建只替換該組別及失效隊伍的公開投影，保留其他組別的有效統計。

`scripts/rebuild-public-boards.mjs --env=prod` 預設唯讀盤點；確認後以 `--apply` 執行。先將兩張看板完整備份到忽略版控的 `tools/backups/`，並新增維護稽核，之後依權威來源重建。原始球隊、比賽、名冊及既有稽核不刪除。

## 驗證範圍

引擎驗證跨階段、淘汰賽、缺失隊伍、重開／取消、作廢事件與兩黃換紅。模擬器直接執行觸發器，驗證刪除、重開、事件作廢、更名與跨組保留。介面涵蓋深淺色、320–1280px、長隊名、組別篩選、牌數說明、有效球隊連結、殘留資料過濾及讀取失敗；另加對應變異測試。
