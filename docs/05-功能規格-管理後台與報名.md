# 05｜功能規格：管理後台與賽前報名

> 對象：主辦單位、ToosterX 營運。桌機優先（現場也要能用手機處理急件）。
> 原則：**現場一定會出錯，所有結果性資料都必須能人工修正，且修正必留痕。**

---

## 1. 後台結構

```
#/admin
├── 儀表板          即時概況、異常提醒、營運指標
├── 賽事設定        Event 基本資料、開關、贊助商
├── 組別與賽制      Division / Format / RankingRule
├── 球隊管理        隊伍、名單、球員證
├── 賽程管理        產生、排定、拖曳調整
├── 場次管理        比分修正、狀態、直播來源
├── 積分與排名      積分榜、手動裁定、最終排名發布
├── 檢錄管理        檢錄狀況、補登、重發 QR
├── 報名審核        線上報名申請
├── Challenge      關卡、玩家、成績、抽獎
├── 獎項            獎項設定與得獎者
├── 工作人員        名冊、角色、場地指派
├── 匯出            CSV / PDF
└── 稽核日誌        全站修改紀錄
```

**異常偵測規則**（自動掃描，出現即進「需要處理」）

| 代碼 | 條件 |
|---|---|
| `SCORE_MISMATCH` | timeline 加總 ≠ match.score |
| `UNRESOLVED_TIE` | standing.hasUnresolvedTie |
| `LATE_KICKOFF` | 排定開賽時間已過 15 分鐘仍為 `scheduled` |
| `STUCK_LIVE` | `live` 狀態超過 賽制時長 × 2 |
| `ROSTER_SHORT` | 檢錄人數低於下限 |
| `NO_STREAM` | 場地直播設為 enabled 但 status 非 live |
| `ADVANCE_BLOCKED` | 階段已完賽但晉級未解算 |

## 3. 賽事設定

| 區塊 | 欄位 |
|---|---|
| 基本 | 名稱、正式名稱、副標、標語、日期、地點、主辦、時區 |
| 開關 | 公開比分、直播、檢錄、Challenge、線上報名（各自可即時開關） |
| 贊助商 | 名稱、層級、Logo、連結、露出版位（首頁／賽程／成果頁） |
| 主視覺 | 主色、Logo、分享圖 |
| 公告 | 跑馬燈公告（可設定時間範圍，顯示在公開端頂部） |

**公告範例**：「因雨勢，10:30 後場次順延 20 分鐘」——這是現場最常用到的功能，必須做在 P0。

## 4. 組別與賽制管理

### 4.1 組別列表

```
┌──────────┬────┬─────┬──────────────────┬────────┬──────┐
│ 組別      │隊數│人制 │ 賽制              │ 狀態    │ 場次  │
├──────────┼────┼─────┼──────────────────┼────────┼──────┤

│ 成人公開組 │ 8  │ 9v9 │ 8隊分組＋交叉排名   │ 進行中  │12/20 │
└──────────┴────┴─────┴──────────────────┴────────┴──────┘
```

### 4.2 賽制設定畫面

```
組別：成人公開組
賽制範本： [ 8隊 兩組循環＋交叉排名 ▾ ]      [ 預覽賽程結構 ]
排名規則： [ 飛達盃預設（對戰關係優先） ▾ ]   [ 檢視判定順序 ]
平手處理： [ PK 大戰 ▾ ]
比賽時間： [ 30 ] 分鐘   半場 [ 15 ] 分鐘
換人上限： [ 7 ] 人次
棄賽判定： [ 3 ] : [ 0 ]
仁慈規則： ☐ 啟用   分差上限 [ 7 ]
```

**「檢視判定順序」**會展開成中文說明（同時也是公開端規程頁的來源）：

```
1. 積分（勝 3 分、和 1 分、負 0 分）
2. 同分隊伍之間的對戰積分
3. 同分隊伍之間的得失球差
4. 同分隊伍之間的進球數
5. 全組得失球差
6. 全組進球數
7. 全組失球數（少者優先）
8. 行為分（紅黃牌罰分少者優先）
9. 主辦單位裁定
```

### 4.3 賽制範本管理

Admin 可新增／複製／編輯 Format。編輯器提供：

- 階段清單（新增 roundRobin / knockout）
- knockout 的 slot 編輯（來源選擇器：積分榜名次 / 某場勝隊 / 某場敗隊）
- 最終排名映射表
- **結構驗證**：檢查是否有循環引用、是否所有名次都有來源、場次數是否合理

> 這是 ToosterX 產品化最重要的資產。FEDA CUP 用到的 4 個範本，未來可直接套到別的盃賽。

## 5. 球隊與名單管理

### 5.1 球隊列表

支援搜尋、依組別篩選、批次操作（指派小組、鎖定名單、發證）。

```
┌────┬──────────────┬────────┬────┬────────┬──────────┐
│ 徽 │ 球隊          │ 組別    │小組│ 名單    │ 狀態      │
├────┼──────────────┼────────┼────┼────────┼──────────┤
│ 🦊 │ 臺中野狼足球隊 │成人公開│ A  │ 14+3 ✅ │ 已鎖定    │
│ 🐯 │ 臺中猛虎足球隊 │成人公開│ A  │ 12+2 ⚠️ │ 未鎖定    │
└────┴──────────────┴────────┴────┴────────┴──────────┘
```

### 5.2 建立球隊的三種方式

| 方式 | 說明 |
|---|---|
| 線上報名核准 | 報名審核通過後自動建立（見 §8） |
| CSV 匯入 | 上傳隊伍＋名單，欄位對照精靈，支援預覽與錯誤標示 |
| 手動新增 | 後台逐筆建立 |

**CSV 範本欄位**

```
隊伍,組別,球員姓名,背號,位置,生日,身分證後四碼,是否隊長,監護人姓名,同意公開照片
臺中野狼,成人公開組,王小明,7,MF,1996-03-14,1234,是,,是
```

匯入驗證：

- 背號同隊不得重複
- 兒童組驗齡：U6（2020/1/1 後出生）、U8（2018/1/1 後）、U10（2016/1/1 後）— 實際基準日由 Admin 設定
- 未成年（< 18 歲）必填監護人姓名與同意欄
- 姓名重複時提示但允許

### 5.3 名單編輯

```
臺中野狼足球隊 · 名單（14 球員 + 3 職員）
[ + 新增球員 ]  [ 匯入 CSV ]  [ 鎖定名單 ]  [ 全部發證 ]

┌────┬──────────┬────┬──────────┬────┬──────────┬──────┐
│背號│ 姓名      │位置│ 生日      │隊長│ 資格      │ 球員證│
├────┼──────────┼────┼──────────┼────┼──────────┼──────┤
│  1 │ 陳守門    │ GK │1994-05-02│    │ ✅ 通過   │ 已發  │
│  7 │ 王小明    │ MF │1996-03-14│ ⓒ │ ✅ 通過   │ 已發  │
│ 18 │ 王阿力    │ FW │2009-11-30│    │ ⚠️ 未成年 │ 未發  │
└────┴──────────┴────┴──────────┴────┴──────────┴──────┘
```

**名單鎖定**：鎖定後球隊自己不可再改，只有 Admin 可調整（記錄 audit）。建議賽前一日 18:00 統一鎖定。

### 5.4 球員證發放

- 單人發證 / 整隊發證 / 全賽事發證
- 產出方式：
  - **線上**：每位球員一個連結 `#/pass/:teamId/:memberId`（含 QR、姓名、背號、隊徽、照片），球隊管理員可統一轉發到隊上群組
  - **列印**：A4 一頁 8 張的球員證 PDF（含 QR、照片、姓名、背號、組別），Cloud Function 產生
- 重發：`qrRevoked = true` 舊證作廢 → 產新 sig → 更新離線名單

## 6. 賽程管理

> **實作狀態（M4-c 6/7，2026-09-04）**：`#/admin/schedule`。
> 演算法在 `js/engine/schedule.js`（種子腳本與後台共用，R-SCHED-001），
> 畫面在 `js/modules/admin/schedule.js`。細節與陷阱見 `CLAUDE.md`。
>
> **與這份規格的差異**：§6.2 畫的拖曳時間軸**沒有做**，改成清單式編輯
> （主辦 2026-09-04 決定）。現場多半是拿手機改一兩場，觸控拖曳在 320px 上
> 既難做對也難測。「整體順延」有做，因為那是雨天真的會按的按鈕。
>
> **規格沒寫、但實作補上的**：分組改成**抽籤**（規章第十四條），
> 種子寫進稽核以便重放；隊數不是 4／6／8 時產生通用範本；
> 發布之前公開端不顯示（`division.schedulePublished`）。

### 6.1 產生賽程

```
組別：成人公開組
[ 1. 指派小組 ]  蛇形自動 / 手動拖曳
[ 2. 產生對戰 ]  依 Format 產生 20 場
[ 3. 排定時間 ]  設定起始時間、場地、每場時長、緩衝、休息下限
[ 4. 檢查衝突 ]  同隊同時段、休息不足、場地重疊
[ 5. 發布賽程 ]  對公開端顯示
```

### 6.2 賽程調整（拖曳）

時間軸視圖（橫軸時間、縱軸場地）：

```
        08:30  09:00  09:30  10:00  10:30  11:00
A場    [第29場][第30場][第31場][第32場][    ][第33場]
B場    [第41場][第42場][第43場][    ][第44場][第45場]
```

- 拖曳改時間與場地，即時檢查衝突並以紅框標示
- 「整體順延」按鈕：選定時間點後，之後所有場次一併順延 N 分鐘（雨天最常用）
- 變更後公開端自動更新，並可勾選「發送公告」

## 7. 積分與排名管理

### 7.1 積分榜檢視

顯示每組積分榜，並在每一列展示 `tieBreakTrace`（判定依據），欄位可展開看細項。

### 7.2 同分人工裁定

當 `hasUnresolvedTie === true`：

```
⚠️ 成人公開組 A組 第2-3名同分且所有條件皆相同

  臺中猛虎   6分  進5 失2 差+3  行為分 -1
  臺中獵鷹   6分  進5 失2 差+3  行為分 -1

  請選擇處理方式：
  ○ 抽籤決定（系統產生，記錄亂數種子供稽核）
  ● 主辦裁定（拖曳排序）
      ⠿ 1. 臺中猛虎
      ⠿ 2. 臺中獵鷹
  裁定理由（必填）：_______________________
  [ 確認裁定 ]
```

裁定後 `standing.manualOverride.enabled = true`，該組排名鎖定不再自動重算（除非 Admin 解除）。

### 7.3 晉級管理

```
成人公開組 · 交叉賽
  ✅ 準決賽①  A1 臺中野狼 vs B2 臺中閃電    已解算 14:02
  ✅ 準決賽②  B1 臺中星光 vs A2 臺中猛虎    已解算 14:02
  ⏸ 5-8名賽① A3 ??? vs B4 ???             等待 A組完賽

[ 🔒 鎖定自動晉級 ]  [ ↻ 重新解算 ]  [ ✏️ 手動指定隊伍 ]
```

### 7.4 最終排名發布

```
成人公開組 最終排名
  🥇 1  臺中野狼    冠軍賽 2-1 勝
  🥈 2  臺中星光
  🥉 3  臺中猛虎
     4  臺中閃電
     5-8 …

  [ 預覽公開頁 ]  [ 📢 發布最終排名 ]
```

發布後才會出現在公開端 `#/results`。

## 8. 報名審核

### 8.1 線上報名表單（公開）`#/register`

```
① 選擇組別        （顯示各組剩餘名額）
② 球隊資料        隊名、簡稱、隊徽上傳、成立年份、所在地、球隊簡介
③ 聯絡人          姓名、手機、Email、LINE
④ 球員名單        逐筆新增 或 上傳 CSV
                  每位：姓名、背號、位置、生日、身分證後四碼、
                        是否隊長、是否守門員、照片（選填）
                  未成年另填：監護人姓名、監護人聯絡電話、
                             ☐ 同意參賽  ☐ 同意公開照片
⑤ 職員名單        總教練、領隊、隊醫…
⑥ 確認送出        顯示規程摘要與同意條款
```

**驗證規則**

| 項目 | 規則 |
|---|---|
| 球員人數 | 5 人制 ≥ 7 人、≤ 12 人；9 人制 ≥ 11 人、≤ 18 人（可設定） |
| 背號 | 1–99，同隊不重複 |
| 年齡 | 依組別基準日自動驗算，超齡直接擋下並說明 |
| 守門員 | 至少 1 名 |
| 隊長 | 恰 1 名 |
| 個資 | 身分證僅收後四碼；不收全碼 |

送出後產生 `registrations` 文件，狀態 `pending`，並寄出／推送確認通知。

### 8.2 審核介面

```
┌─────────────────────────────────────────────┐
│ 臺中野狼足球隊 · 成人公開組 · 14人           │
│ 聯絡人 呂維哲 0985-679-923                  │
│ 送出時間 2026-09-12 21:04                   │
│                                             │
│ 名單檢核                                     │
│  ✅ 人數 14（符合 11–18）                    │
│  ✅ 背號無重複                                │
│  ✅ 年齡符合                                  │
│  ⚠️ 2 位球員未上傳照片                        │
│                                             │
│ [ 核准並建立球隊 ]  [ 退回補件 ]  [ 拒絕 ]    │
└─────────────────────────────────────────────┘
```

- **核准**：建立 `teams` + `members`，回填 `registration.createdTeamId`，通知聯絡人
- **退回補件**：填寫原因，聯絡人收到連結可回頭修改後再送
- **拒絕**：填寫原因並通知

### 8.3 名單異動申請

名單鎖定後，球隊可提出異動申請（換人／改背號／補球員），Admin 審核後生效。異動一律記錄 audit。

## 9. 檢錄管理

```
第31場 檢錄狀況
臺中野狼  12/14  ✅ 已確認 09:18
```

- 新增工作人員：輸入姓名 → 產生一次性邀請 QR／連結 → 對方用 LINE 掃碼即完成綁定
- 角色與指派可隨時調整，**立即生效不需重登**（沿用 FC 的 `rolePermissions` 動態權限機制）
- 「踢除裝置」：緊急停權

## 13. Admin 操作的安全門檻

| 動作 | 門檻 |
