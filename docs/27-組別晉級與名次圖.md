# 組別晉級與名次圖

使用者確認：保留既有組別頁設計，新增「晉級／名次圖」。四強以底下四支隊伍、中間兩支晉級者、頂端冠軍呈現；季軍與其他名次賽另列。2026-10-09 授權完成後上線。

## 設計與資料契約

- 使用實際 `config/formats.formats[division.formatId]` 的 slots、TeamSource、finalRankingMap 畫關係；不得依隊數猜賽制或硬寫 SF1/F1 連線。
- 正式資料核對：女子 `F4_RR_SEMIFINAL` 為四來源、三層；U6/U8/U10 `F6_GROUP_TOP_SEED_BYE` 與成人 `F8_GROUP_TOP_SEED_BYE` 含小組第一輪空，冠軍支線為六來源、四層。兩種輪空設定的甲乙組銜接並不相同，必須沿設定逐一追溯。
- 四強先以 320px 可容納的四格顯示，長隊名完整換行。多輪圖保留每格可讀寬度，在圖內左右捲動並提供文字提示。SVG 依實際節點位置重畫，視窗與字體尺寸變動不脫線。
- 圖中每格代表隊伍或待定來源，點擊開啟該隊正在參與的那一場。最上格代表該支線名次；沒有場次文件的格不能點入不存在頁面。
- 小組來源只展示場次已填入的隊伍；不从尚在進行的積分榜推測晉級。未解算顯示甲組第N名／指定場次勝隊等來源。
- 使用既有引擎 `resolveTeamSource` 讀取完賽、確認或判定勝之 result.winner。比賽中領先、平局、未決 PK、取消場次均不能產生冠軍。正規分與 PK 分開呈現，沿用兒童組比分上限。
- 上游重開／改判與下游尚未同步時撤回舊晉級者；新隊名不可附上舊對戰比分。資料重複、來源缺失或循環設定顯示整理中，不任選一場。
- 同時僅三個公開資料監聽：組別、賽制設定、該組場次。經 store.hold 回收；撤回發布立刻隱藏圖，離線快取顯示提示。完全不讀 members、不更動賽制、名單、比分或後端規則。
- 保留原積分榜／賽程／球隊入口；支援 `#/division/:id?tab=bracket` 與 `#/division/:id/bracket`。

## 施工階段、步驟與做法

1. 核對階段：從最新 origin/main 建立隔離分支；唯讀查詢正式 config、divisions、matches，確認發布、matchKey、stageId 與小組顯示名稱。既有工作區未提交變更不混入本次。
2. 資料階段：新增純展示模型，建立槽位→實際場次映射；驗證唯一性、來源完整性與非循環性。以 finalRankingMap 找冠軍入口，遞迴追溯勝隊來源；敗隊支線以其他名次賽呈現。
3. 介面階段：共用現有分頁、頁首、色票、卡片、場次導頁與比分格式；新增由下往上節點與連線。即時快照重畫時保留捲動與焦點；卸載時回收 ResizeObserver 與監聽。
4. 驗證階段：跑下列驗收、既有完整 unit/E2E 回歸、版本／離線資源／變異錨點檢查；檢視實際 320px、手機與桌機的深淺截圖。發現差異先修正再重跑受影響測試。
5. 發布階段：執行 bump-version，讓新增模組進入離線清單；凍結提交與版本後依下節先 Demo 再正式。

## 驗收

|情境|合格條件|
|---|---|
|女子四強|四來源、兩勝隊、一冠軍；來源依設定 2/3、1/4|
|六／八隊輪空|六來源、四層；第一名直接位於輪空層；甲乙組連線逐一符合正式設定|
|直接決賽／純循環|不製造不存在的準決賽；循環組提示查看積分榜|
|比賽中／PK／判定勝|不提早顯示冠軍；使用結果判定，PK 明列；判定勝可顯示晉級|
|改判／重開|舊晉級者與冠軍撤回，舊比分不能移到新隊名|
|資料異常|缺場保留待排定結構、無失效連結；重複 key、循環或缺來源顯示整理中|
|發布／離線|未發布不露對戰圖，撤回即隱藏；快取標示且恢復連線能更新|
|隱私／文字|不請求私人名冊；隊名以 textContent 顯示，HTML 不執行|
|手機／鍵盤|320px 整頁無橫溢；多輪只在圖內捲動；按鈕有焦點與場次名稱|
|生命週期|切分頁後監聽回收；來回進入不累積連線或 ResizeObserver|

## 佈署與回復

1. 發布前重新 fetch main/demo；若遠端前進，整合後重跑受影響驗證、重新核定提交。禁止 force push 覆蓋別人的發布。
2. 先將本次提交快轉至 demo。等 Cloudflare Pages 成功，讀取 Demo 的版本與新模組，實際開組別頁確認新分頁、對戰圖與場次導頁。
3. Demo 通過後將相同提交推至 main，等正式 Pages 成功；核對 cup.toosterx.com 的 HTML、config、SW 版本及對戰圖模組，檢查女子、兒童、成人三種結構與公開資料監聽。
4. 本次只需靜態站發布，沒有資料遷移、Firestore rules 或 Functions 變更。不得為畫圖重排賽程或修改生產比分。
5. 若新頁異常，回復本次程式提交並重新 bump／發布；不回滾賽事資料。保留測試與部署證據，說明通過、失敗、未跑各項。
